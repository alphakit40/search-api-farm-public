# Ебанутый ресёрч — deepresearch с верификацией и gap-бэкэджем

Отличие от скилла `deepresearch`: тот собирает много источников и честно их сливает.
Этот — строит проверенные цепочки и сам себя атакует. Веришь не источнику, а верифицированной ссылке.

Почему это отдельный скилл: deep-research-агенты выдумывают 3–13% citation URL,
 причём DR-режимы галлюцинируют БОЛЬШЕ обычного поиска
 (gemini-2.5-pro-deepresearch 13.3% против 3.0% у claude-with-search,
 arxiv.org/abs/2604.03173). Один сбор без верификации = уверенная ложь.

## Пайплайн: 6 стадий, циклы обязательны

```
0 HITL → 1 PLAN → 2 EXPLORE → 3 SYNTHESIZE →(дыры?)→ 2 EXPLORE → 4 VERIFY → 5 REPORT
                                            ↑ макс 2 цикла бэдкежа ↑
```

### 0. HITL-гейт (не жечь токены на неверном ТЗ)
План одним блоком: тема → 5–7 подзапросов → каналы на каждый → бюджет (N источников).
Пользователь утверждает или правит одной итерацией. Без «ок» не стартовать.
Если пользователь уже сказал «делай всё сам» — гейт пропускается, план фиксируется в отчёте.

### 1. PLAN — known-unknowns ledger
- **Ledger дыр**: ДО старта список «что мы не знаем» (5–10 пунктов).
- **Бюджет** на каждый подзапрос: N источников + таймбокс.
- **Комплементарность**: перед запуском каждого запроса ответить —
  чем его ответ ОТЛИЧАЕТСЯ от уже собранного? Повтор = не запускать.
- **Stop-критерий**: дыра закрыта = 2 независимых источника ИЛИ явно «не нашлось».

### 2. EXPLORE — веер по каналам (два прохода)
**Discovery-пасс** (только titles/URLs, −70% шума) → отбор → **Extraction-пасс** по отобранному.

Каналы (все через subprocess, `--json` обязателен):
```
# web-веер
deep_research(topic, subqueries=4, sources=10, fresh=true)     # searchmcp MCP
research(query="<подзапрос>", sources=8)                        # searchmcp MCP
# full-text (firecrawl: пул ключей с авторотацией)
python "$RSTACK_PATH" fc search "QUERY" 5 --json
python "$RSTACK_PATH" fc scrape URL --json
# rstack-каналы
python "$RSTACK_PATH" yt search|transcript|comments ... --json
python "$RSTACK_PATH" rss news "QUERY" 10 en --json
python "$RSTACK_PATH" reddit SUBREDDIT 10 --json
python "$RSTACK_PATH" arxiv "QUERY" 5 --json
python "$RSTACK_PATH" openalex "QUERY" 5 --json
python "$RSTACK_PATH" hn "QUERY" 10 --json
python "$RSTACK_PATH" gh issues "TOOL problem" 10 --json
python "$RSTACK_PATH" twg "QUERY" 15 --days 7 --verify --json
python "$RSTACK_PATH" s2 "QUERY" 5 --json
python "$RSTACK_PATH" wayback URL 3 --json
```
- `fc scrape URL --cookies "k=v; k2=v2"` — контент за логином (cookies.txt-экспорт).
- Персональные данные (если пользователь дал): cookies-пул, Chrome History
  (приоритизация доменов), Zotero local API — как seed/фильтр.

### 3. SYNTHESIZE — с gap-бэкэджем
- Дедуп по URL + hash; одна мысль из N источников = один факт, сильнейшая ссылка.
- Синтез ПОИСК дыр в ledger → нашёл → вернуться в EXPLORE конкретно по ним
  (макс 2 цикла, каждый цикл логируется в отчёт: «цикл 2: закрыто 3 дыры из 5»).
- Противоречия: обе версии рядом, у каждой источник.

### 4. VERIFY — здесь начинается ебанутость
1. **Citation-чекер** (детерминированный, не LLM): каждая inline-цитата [URL] отчёта →
   - URL жив? (fc scrape / extract; 404 → wayback; мёртв в архиве → пометка)
   - топически релевантен?
   - факт подтверждается текстом источника? (читать full-text, не сниппет)
   Провал любой проверки → факт помечен ⟂ или выкинут. Отчёт содержит счётчик: X/Y цитат верифицировано.
2. **Adversarial-критик**: топ-5 спорных фактов → критик из ДРУГОГО семейства моделей
   (одна модель с собой спорит почти бесполезно — эффект даёт разница bias-профилей,
   arxiv.org/abs/2605.03042) → adjudicator выносит вердикт.
3. **E-Conf теги**: после каждого блока отчёта — [высокая|средняя|низкая уверенность]
   (не «уверен/не уверен», а evidence-based: сколько независимых подтверждений).

### 5. REPORT
- **Executive Summary** — вывод + уровень уверенности + счётчик верификации.
- **Таблица фактов**: | факт | источник [URL, дата] | канал | E-Conf |
- **Противоречия** — обе стороны + вердикт adjudicator'а.
- **Провалы верификации** — что НЕ прошло чекер (отдельная секция, это результат).
- **Что не нашлось** — явно (после 2 циклов бэдкежа).
- **Ингест-хук**: все верифицированные источники → knowledge_base (Obsidian 30-Knowledge-Base)
  с пометкой provenance (когда/откуда) — следующий ресёрч стартует с этой базы.

## Success
- Счётчик верификации в отчёте (X/Y цитат живы и подтверждают факт).
- Каждый спорный факт прошёл adversarial-проверку или помечен ⟂.
- Gap-бэкэдж реально запускался (или дыр не было — с доказательством ledger'а).
- E-Conf на каждом блоке; «Что не нашлось» присутствует.

## Failure modes
| Симптом | Действие |
|---|---|
| fc: all keys exhausted (401/402) | Ключи кончились → `extract` searchmcp / `rstack wayback`; пометить «full-text частично» |
| fc 429 (rate) | Автотация внутри rstack уже пробует следующий ключ; если все — как выше |
| DDG SERP блок | веер на других движках; tavily MCP резерв |
| twg мёртв | `rstack tw search` (twitterapi.io) |
| S2 429 | `rstack openalex` |
| wayback timeout | 1 ретрай; второй = «архив пуст» |
| Критик того же семейства недоступен | Пометить «adversarial пропущен» — НЕ имитировать другим промптом той же модели |
| Дыра не закрывается 2 цикла | В «Что не нашлось» с перечислением испробованных запросов |

## Gotchas
- `--json` на rstack обязателен; fc возвращает `markdown` полным текстом — читать поле, не сниппет.
- Discovery-пасс ПЕРВЫМ: не тащи full-text всего подряд — выбери 10–15 URL из 50+.
- Верификация НЕ опциональна: это то, за что этот скилл называется ебанутым.
- LLM-проверку дублируй детерминированной (citation-чекер скриптом/чтением, не «мне кажется ок»).
- Никогда не доверяй одному источнику спорного факта — 2 независимых ИЛИ пометка.

## Тулинг (этот репо)

Опциональные помощники в `research/` (скилл работает и без них, с любым поисковым стеком):

```bash
cd research/
python -u harvest.py <topic> --topics topics.example.json   # мультиканальный сбор -> raw/
python -u digest.py [topic]                                 # карта источников для синтеза
python -u cite_check.py [REPORT.md]                         # детерминированный citation-чекер
python -u adversarial_critic.py [facts.json]                # критик через GATEWAY_URL (другое семейство!)
python -u gap_backedge.py scrape|query [gap.json]           # второй цикл по дырам
```

Env: `EXA_KEYS` (csv, ротация), `TAVILY_KEY`, `YOU_KEY`, `RSTACK_PATH`,
`GATEWAY_URL`, `CRITIC_MODEL`, `RESEARCH_ROOT`, `SEARCH_API_FARM_SECRETS`.
